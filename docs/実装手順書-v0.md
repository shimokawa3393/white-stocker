# SacSak v0（MVP）実装手順書

対象：`docs/タスクタイムラインアプリ設計-v1.md` / `docs/CLAUDE.md` に基づく v0 スコープのみ。
本手順書に無いもの（色タグ、通知、テンプレ、課金、D&D、オンボーディング等）は着手しない。

## 0. 前提確認

- 現状のXcodeプロジェクト（`WhiteStocker/`）はテンプレート初期状態。`Item` モデル・`ContentView` のList/Detailはサンプルコードなので**すべて置き換える**。
- Bundle名・アプリ名は `WhiteStocker`（プロジェクト名）のまま進めるか `SacSak` に変更するかは要確認事項（下記「未確定事項」参照）。本手順書ではファイル構成に影響しないため、コード側は汎用的な命名にする。
- v0で作るのは以下の2つのみ：
  - Task CRUD（名前・メモ・所要時間）
  - タイムラインへのタップ配置（空きスロット判定・15分スナップ・duration上書き）

## 2. 実装ステップ

### Step 1. プロジェクトのクリーンアップ
- `Item.swift` を削除
- `ContentView.swift` のサンプルList/Detail実装を削除し、`TimelineView` を起点に差し替え準備
- `WhiteStockerApp.swift` の `Schema` を `Item.self` → `Task.self, Placement.self` に変更
- 表示名（ホーム画面アイコン下の名前）を `SacSak` にする。プロジェクト名・Bundle IDは `WhiteStocker` のまま変更しない
  - `project.pbxproj` の両ビルド設定（Debug/Release）に `INFOPLIST_KEY_CFBundleDisplayName = SacSak;` を追加（現状未設定のため新規追加）

### Step 2. データモデル実装（`Models/`）
設計書のスキーマ通りに実装。

```swift
// Task.swift
@Model
final class Task {
    var id: UUID
    var name: String
    var memo: String?
    var durationMin: Int
    var createdAt: Date
    var deletedAt: Date?

    init(name: String, memo: String? = nil, durationMin: Int, createdAt: Date = .now) {
        self.id = UUID()
        self.name = name
        self.memo = memo
        self.durationMin = durationMin
        self.createdAt = createdAt
    }
}

// Placement.swift
@Model
final class Placement {
    var id: UUID
    var task: Task
    var date: Date          // 配置日（日付のみに正規化して保持）
    var startTime: Date
    var durationMin: Int
    var createdAt: Date

    init(task: Task, date: Date, startTime: Date, durationMin: Int, createdAt: Date = .now) {
        self.id = UUID()
        self.task = task
        self.date = date
        self.startTime = startTime
        self.durationMin = durationMin
        self.createdAt = createdAt
    }
}
```

**注意点：**
- `Task` は論理削除（`deletedAt`セット）。物理削除しない。一覧クエリは `deletedAt == nil` でフィルタ
- `Placement.durationMin` は生成時に `Task.durationMin` をコピーするが、以後は独立編集可能
- `Placement.date` は必ず `Calendar.current.startOfDay(for:)` を通してから保存・クエリする（生成時・日付ページング時の両方）。素の `Date()` をそのまま入れない

### Step 3. 空きスロット計算ロジック（`Logic/SlotFinder.swift`）
Viewから独立させ、単体テスト可能な純粋関数として実装する（**ここがv0の心臓部**）。

責務：
1. 指定日の全 `Placement` を `startTime` でソート
2. 指定した1時間Row内の空き区間を算出（既存Placementと重複する区間を除外）
3. 15分刻みの候補スロットに丸めて返す

```swift
struct SlotFinder {
    /// 指定Rowの時間帯内で、既存Placementと被らない空き区間を返す
    static func availableSlots(
        rowStart: Date,
        rowEnd: Date,
        existingPlacements: [Placement],
        stepMinutes: Int = 15
    ) -> [DateInterval] { ... }

    /// 指定開始時刻から見て、空きが確保できる最大分数（クイック選択の妥当性チェック用）
    static func maxAvailableDuration(
        from start: Date,
        existingPlacements: [Placement]
    ) -> Int { ... }
}
```

先にこのロジックのユニットテストを書いてから実装すると境界値（Rowまたぎ、隣接Placementの端点一致など）を担保しやすい。

### Step 4. タスク一覧・編集（`Views/TaskList/`）
- `TaskListView`：`@Query(filter: #Predicate<Task> { $0.deletedAt == nil })` で一覧表示。スワイプ削除は論理削除（`deletedAt = .now` をセット）
- `TaskEditSheet`：name（必須）・memo（任意）・durationMin（15分刻みのステッパー or Picker）を持つモーダル。新規作成と編集を共通化

### Step 5. タイムライン表示（`Views/Timeline/TimelineView.swift`）
- 縦：0:00〜24:00 を1時間刻みの `TimelineRowView` で `ScrollView` 表示
- 横：`TabView(.page)` またはページング可能な `ScrollView` + `.scrollTargetBehavior(.paging)` で日付切り替え（カレンダーピッカーは実装しない）
- 各Rowに、その日の `Placement` を `startTime`/`durationMin` から算出した高さでオーバーレイ描画（`PlacementBlockView`）
  - 1時間をまたぐPlacementは複数Row分の高さで描画（「タップ判定＝1Row」と「見た目＝時間軸比例」を明確に分離した実装にする。具体的には、Row自体はタップ領域のみを持ち、Placementブロックの描画は日全体のZStack上に絶対配置する構成が扱いやすい）
  - 同一Row内の複数Placementは横並び or 重ならないよう左右分割で描画

### Step 6. 配置フロー（`SlotPickerSheet.swift`）
Rowタップ時のフロー：
1. `SlotFinder.availableSlots` でそのRowの空き区間を算出し提示
2. 空きスロットをタップ → Task一覧（`deletedAt == nil`）から選択
3. 選択したTaskの `durationMin` をデフォルト表示 → そのまま確定 or 15/30/45/60分クイック上書き
   - 上書き時は `SlotFinder.maxAvailableDuration` で空きを超えないか検証
4. 開始時刻は15分刻みにスナップ済みの値のみ選択可能にする
5. 確定で `Placement` を生成し `modelContext.insert`

### Step 7. 配置の編集/削除（`PlacementEditSheet.swift`）
- 既存ブロックタップ → `startTime` / `durationMin` の編集、または削除（物理削除でよい。Placementは在庫ではなく配置の実体のため）
- 編集時も `SlotFinder` で他Placementとの重複を再検証

### Step 8. 結線・動作確認
- `TimelineView` をアプリのルート（`WindowGroup` の初期View）にする
- タスク一覧への導線（ツールバーボタン等）を `TimelineView` に設置
- 実機/シミュレータで以下を確認：
  - Task登録→タイムライン配置→編集→削除の一連の動線
  - Rowまたぎブロックの描画
  - 同一Row内の複数配置
  - 空きスロットが無いRowをタップした場合の挙動（何も配置できない旨を示す）

## 3. 実装順序のまとめ（依存関係順）

```
1. モデル（Task / Placement）
2. SlotFinder（ユニットテスト付き）
3. TaskListView + TaskEditSheet（Task CRUDが先に動く状態を作る）
4. TimelineView（表示のみ、配置ゼロの状態で見た目を作る）
5. SlotPickerSheet（配置フローを繋ぐ）
6. PlacementBlockView（Rowまたぎ・複数配置の描画）
7. PlacementEditSheet（編集/削除）
8. 結線・通し動作確認
```

## 5. 確定事項

- プロジェクト名／Bundle IDは `WhiteStocker` のまま。表示名（CFBundleDisplayName）のみ `SacSak` にする
- `Placement.date` は `Calendar.current.startOfDay(for:)` で00:00に正規化した `Date` 型として保持する。生成・クエリ双方でこの正規化を必ず経由すること（デバイスのタイムゾーンが変わらない前提）
